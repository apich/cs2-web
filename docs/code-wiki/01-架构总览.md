# 01 · 架构总览

## 1. 项目定位

`cs2-web` 是一个**纯网页端**的 Dust II 竞技射击游戏，基于开源项目 [ETO-ze/dust2-web](https://github.com/ETO-ze/dust2-web) 深度重构。它不是 CS2 官方客户端或 Source 2 引擎的移植，而是独立实现的游戏逻辑 + 权威服务器联机框架。核心体验包括：爆破/死斗两种对局、5v5 房间联机、BOT 填充、武器/皮肤/探员装载、投掷物、脚步与弹道系统。

## 2. 技术栈与进程模型

```
┌────────────────────────────────────────────────────────────────┐
│                        浏览器 (客户端)                          │
│  index.html ──> client/main.js                                 │
│   ├── Three.js 渲染（主场景 scene + 武器层 gunScene）            │
│   ├── three-mesh-bvh 地图碰撞                                    │
│   ├── 本地移动预测 / 远端玩家插值                                │
│   ├── 输入捕获（键鼠 + 触屏）→ 30Hz 上行 input                  │
│   └── WebSocket 客户端                                          │
└───────────────────────┬───────────────────────────────────────┘
                        │ /ws (WebSocket，房间状态 + 事件)
┌───────────────────────▼───────────────────────────────────────┐
│                     Node.js 权威服务器 (server)                  │
│   server/index.js ──> GameRoom (每房间一个)                      │
│   ├── 30Hz tick 权威模拟（移动/射击/命中/购买/爆破）             │
│   ├── 15Hz snapshot 下推（序列化房间完整状态）                   │
│   ├── BOT AI（感知/瞄准/战术/走位）                             │
│   ├── HTTP 静态托管（dist/ 构建产物 + public/ 素材）            │
│   └── /health 健康检查                                          │
└────────────────────────────────────────────────────────────────┘
```

- **权威服务器**：所有判定（移动合法性、弹药、命中、血量、购买、爆破结果）都在服务端完成，客户端只提交「意图」（按键/朝向/射击时间戳），不能伪造结果。
- **确定性弹道**：双端使用同一套基于 `shotId` 的确定性 RNG（`shared/aim.js` 的 `shotRng`），使本地预渲染的弹道轨迹与服务端命中结果一致。
- **移动预测**：客户端以 60Hz 预测自身移动，服务端每 15Hz 用快照「确认重放」（reconcile），见 `client/movement-prediction.js` 与 `shared/movement-commands.js`。

## 4. 分层职责

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 表现层 | `client/` + `index.html` | 3D 渲染、武器视模、HUD、菜单、音频、特效 |
| 网络层 | `server/index.js`（接入）+ `client/main.js`（连接与收发） | WebSocket 握手、消息路由、限流、心跳 |
| 逻辑层（权威） | `server/game.js` 及 `server/*` | 游戏状态机、回合/比分、命中、购买、爆破、BOT |
| 逻辑层（共享） | `shared/` | 规则常量、武器数值、弹道、移动物理、CS 设置换算 |
| 数据层 | `public/assets/`、`config/assets-lock.json` | 地图几何/碰撞、模型、贴图、音效清单 |

## 5. 数据流

### 5.1 玩家动作上行（客户端 → 服务端）

1. `client/main.js` 的 `frame()` 以 30Hz 调用 `sendInput(input)`，把当前 `currentInput()`（移动轴、朝向 `lookYaw/lookPitch`、跳跃/换弹 ID、开火、槽位、`zoomLevel` 等）发给服务端。
2. 服务端 `server/index.js` 收到 `input` → `GameRoom.receiveInput(id, msg)`，经 `sanitizeInput` 清洗后写入玩家 `input`。
3. `GameRoom.tick()` 每 30Hz 基于权威状态推进移动、射击、投掷、换弹、购买判定。

### 5.2 状态下行（服务端 → 客户端）

1. `GameRoom.tick()` 每 2 个 tick（即 15Hz）调用 `room.snapshot()`，`JSON.stringify` 后广播给房间内所有 socket。
2. 客户端 `handleSnapshot()` 解析快照，更新本地 `self/actors`，同步 HUD、特效、音频与远端玩家插值。

### 5.3 事件驱动（离散事件）

服务端通过 `GameRoom.emit(type, fields)` 把离散事件（`shot`、`hit`、`kill`、`grenade_thrown`、`bomb_exploded`、`weapon_dropped` 等）附加到快照的 `events` 数组，客户端 `handleEvent()` 去重后分发到对应子系统（特效/音频/UI）。事件带递增 `id`（`${code}:${eventCounter}`），客户端用 `handledEvents` 集合去重。

## 6. 关键全局/常量

- `server/game.js`：`TICK_RATE=30`（模拟频率）、`SNAPSHOT_RATE=15`（下发频率）、`RULES`（回合/购买/爆破/重生时长）、`MAX_PLAYERS=10`。
- `shared/match-rules.js`：`MATCH_RULES`（MR12 常规 13 胜、加时 MR3、死斗 100 杀）、`defuseDecision()` 胜负/换边/重置资金决策。
- `shared/movement-commands.js`：`MOVEMENT_HZ=60`（移动预测步进频率）。

## 7. 目录边界与模块置信

- 客户端与服务端通过 `shared/` 复用同一套数值与算法，避免双端漂移（尤其弹道 RNG、移动物理、武器属性）。
- `client/` 与 `server/` 永不直接互相 import；所有跨端接口都走 WebSocket 消息（协议详见 [server/PROTOCOL.md](../../server/PROTOCOL.md)）。
